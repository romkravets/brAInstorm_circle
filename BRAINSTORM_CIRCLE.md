## 1. Ідея та концепція {#ідея}

**Brainstorm Circle** — веб-застосунок для оркестрування мозкового штурму між кількома AI-моделями (Claude, Gemini, GPT, Mistral тощо) **без використання API та без оплати за токени**.

### Проблема

Кожен великий AI-провайдер — окрема вкладка браузера. Коли людина хоче отримати "перехресний" аналіз від кількох моделей, вона:
- Копіює питання вручну в кожну вкладку
- Губить контекст між відповідями
- Не має структури для порівняння
- Втрачає історію сесії при перезавантаженні

### Рішення

Центральний "диригент" — одна вкладка, де:
- Зберігаються відповіді всіх AI-учасників
- Автоматично генеруються промпти для перехресного аналізу
- Відбувається дистиляція спільної істини
- Вся робота зберігається між сесіями

### Ключова метафора

**Круглий стіл**: кожен AI — учасник з власною роллю та кольором. Ти — модератор. Питання — в центрі. Раунди — як тури дискусії.

## 2. Критичний аналіз поточної версії {#критика}

### ❌ Критичні проблеми

| Проблема | Вплив | Пріоритет |
|---|---|---|
| Немає localStorage — дані губляться при F5 | Критично для реального використання | P0 |
| Немає поля для питання в центрі уваги | Контекст губиться при перегляді відповідей | P0 |
| Картки AI розміщені в рядок — при 3+ AI стає тісно | Незручний UI на 3-4 учасниках | P1 |
| Промпти відображаються внизу — треба скролити | Порушує flow, людина губить контекст | P1 |
| Немає режимів роботи (дебати / синтез / критика) | Всі кнопки однакові — незрозуміло навіщо кожна | P1 |
| "Дистиляція" генерує шаблонний текст з `...` | Користувач очікує реального синтезу | P2 |
| Немає онбордингу / підказок для нового користувача | Незрозуміло з чого починати | P2 |
| Кольори учасників — хардкод, важко читати в темній темі | Доступність | P2 |
| Немає експорту сесії | Не можна поділитись результатом | P3 |
| Один промпт-шаблон на кнопку — не враховує контекст | Промпти занадто generic | P3 |

### ⚠️ Дизайн-проблеми

- Назва "Brainstorm Circle" є, але кола немає — метафора не втілена візуально
- Кнопки "Оскаржити", "Поглибити", "Надіслати іншим" — 3 кнопки під кожною карткою захаращують UI
- Вижимка — внизу, але це найважливіше — мало бути на виду
- Немає індикатора "прогресу" раунду (скільки AI вже відповіли)
- Таблетки-раунди (Раунд 1, Раунд 2) — хороша ідея, але немає можливості перейменувати

### ✅ Що працює добре

- Концепція кольорових учасників — інтуїтивно зрозуміла
- Кнопка "+ Додати AI" — правильна фіча
- Логіка збереження/відновлення раунду — правильна
- Промпти з контекстом питання — дуже корисно
- Архів раундів внизу — правильне місце

## 3. Що треба змінити {#зміни}

### Версія 2.0 — пріоритетні зміни

#### Структура сторінки (новий layout)

```
┌─────────────────────────────────────────────────┐
│  HEADER: назва + статус сесії + кнопки дій      │
├─────────────────────────────────────────────────┤
│  ПИТАННЯ (велике, в центрі уваги)               │
│  + вибір режиму: [Синтез] [Дебати] [Критика]    │
├──────────────┬──────────────────────────────────┤
│ УЧАСНИКИ     │  АКТИВНА КАРТКА (поточний AI)    │
│ (ліва панель │  + промпт для копіювання         │
│  з аватарами │  + індикатор заповненості        │
│  та статусом)│                                  │
├──────────────┴──────────────────────────────────┤
│  ДИСТИЛЯЦІЯ (завжди видима, розкривається)      │
├─────────────────────────────────────────────────┤
│  РАУНДИ + АРХІВ (горизонтальна таблетки)        │
└─────────────────────────────────────────────────┘
```

#### Режими роботи

```
СИНТЕЗ       — AI доповнюють один одного, шукають спільне
ДЕБАТИ       — AI сперечаються, критикують позиції інших
КРИТИКА      — кожен AI оцінює відповідь попереднього
ГЛИБИНА      — кожен раунд поглиблює попередній
```

#### Покращений промпт-генератор

Промпт має враховувати:
1. Режим роботи (синтез / дебати / критика)
2. Раунд (перший — без контексту, другий+ — з контекстом попередніх)
3. Конкретного AI-отримувача (Claude vs Gemini мають різні сильні сторони)
4. Кількість вже отриманих відповідей

## 4. Архітектура та структура {#архітектура}

### Концептуальна модель даних

```
Session
├── id: string
├── createdAt: timestamp
├── updatedAt: timestamp
├── title: string          // "MikroTik failover аналіз"
├── question: string       // центральне питання
├── mode: SynMode          // 'synthesis' | 'debate' | 'critique' | 'depth'
├── participants: Participant[]
└── rounds: Round[]

Participant
├── id: string
├── name: string           // "Claude", "Gemini", "GPT-4o"
├── color: ColorConfig
├── role: string           // "Аналітик", "Критик", "Синтезатор"
└── url: string            // посилання на чат (опціонально)

Round
├── id: number
├── label: string          // "Раунд 1", можна перейменувати
├── responses: Record<participantId, string>
├── synthesis: string
├── promptsGenerated: Record<participantId, string>
└── completedAt: timestamp | null

ColorConfig
├── dot: string            // основний колір (#534AB7)
├── bg: string             // фон картки (#EEEDFE)
├── text: string           // текст (#3C3489)
└── border: string         // рамка (#AFA9EC)
```

### Потік даних

```
User Input
    ↓
State Manager (JS class)
    ↓
localStorage (автосейв кожні 2с)
    ↓
UI Renderer (re-render тільки змінені блоки)
    ↓
Prompt Generator (враховує mode + round + context)
    ↓
Clipboard API
```

### Принципи UX

1. **Питання завжди видиме** — при скролі вниз питання фіксується у хедері (sticky)
2. **Промпт — поруч з карткою**, не внизу — відкривається у popup або sidebar
3. **Автосейв** — без кнопки "Зберегти", індикатор "Збережено 2хв тому"
4. **Пустий стан** — при відкритті показує онбординг: 3 кроки що робити
5. **Режим фокусу** — клік на картку AI розгортає її на весь екран для зручного читання

## 7. UX-флоу {#ux}

### Флоу нового користувача

```
1. Відкриває застосунок
   → Бачить онбординг: "Введи питання → Постав кожному AI → Порівняй"
   → Два учасники вже є (Claude + Gemini)

2. Вводить питання
   → Поле підсвічується, підказка: "Чим конкретніше — тим кращі відповіді"

3. Копіює питання в Claude (кнопка "Відкрити Claude")
   → Отримує відповідь → вставляє в картку

4. Натискає "Надіслати Gemini"
   → Промпт генерується → копіює → відкриває Gemini → вставляє

5. Gemini відповідає → вставляє в картку Gemini

6. Натискає "Дистилювати"
   → Бачить синтез з виділеними спільними та різними точками

7. Натискає "Новий раунд" → процес повторюється глибше
```

### Флоу досвідченого користувача

```
1. Відкриває застосунок — бачить збережену сесію
2. Продовжує з Раунду 3
3. Додає GPT-4o як третього учасника
4. Генерує мульти-промпт (всі відповіді → для одного AI)
5. Експортує фінальну дистиляцію в Markdown
```

## 8. Технічний стек {#стек}

### Варіант A — Pure HTML/JS (поточний, рекомендований для MVP)

```
index.html          — весь застосунок в одному файлі
├── CSS             — CSS Variables, без фреймворків
├── Vanilla JS      — класи, localStorage API
└── No dependencies — працює офлайн, відкривається локально
```

**Плюси**: нульова залежність, миттєвий старт, легко ділитись (один файл)
**Мінуси**: складно масштабувати понад ~1500 рядків

```
│   └── storage.ts          — localStorage wrapper
├── components/
│   ├── QuestionBar/
│   ├── ParticipantCard/
│   ├── PromptPanel/
│   ├── SynthesisBlock/
│   ├── RoundTabs/
│   └── HistoryArchive/

│   ├── useSession.ts
```

## 9. localStorage схема {#storage}

```typescript
// Ключ: 'bc_session_current'
interface StoredSession {
  version: '2.0';
  session: {
    id: string;
    title: string;
    question: string;
    mode: 'synthesis' | 'debate' | 'critique' | 'depth';
    createdAt: number;
    updatedAt: number;
    participants: Array<{
      id: string;
      name: string;
      color: { dot: string; bg: string; text: string; border: string };
      role: string;
    }>;
    rounds: Array<{
      id: number;
      label: string;
      responses: Record<string, string>;
      synthesis: string;
      createdAt: number;
    }>;
    currentRound: number;
  };
}

// Ключ: 'bc_sessions_index'
// Список всіх сесій для майбутньої multi-session підтримки
interface SessionIndex {
  sessions: Array<{
    id: string;
    title: string;
    updatedAt: number;
    participantCount: number;
    roundCount: number;
  }>;
}

// Автосейв кожні 2 секунди (debounced)
// Максимум: 50 раундів, 10 учасників, 10 сесій
// При перевищенні — видаляти найстаріші
```

## 10. Компоненти детально {#компоненти}

### QuestionBar

```
Вхід: question (string), mode (SynMode)
Вихід: onQuestionChange, onModeChange

Стани:
  - empty: показує placeholder + підказку
  - focused: підсвічує рамку акцентом
  - filled: показує кількість слів + кнопку "Копіювати питання"

Режими (tabs під полем):
  [Синтез]  [Дебати]  [Критика]  [Глибина]
  Кожен змінює логіку генерації промптів
```

### ParticipantCard

```
Вхід: participant, response, roundIndex
Вихід: onResponseChange

Стани картки:
  - empty:    рамка пунктиром, "Вставте відповідь..."
  - filled:   суцільна рамка кольором учасника
  - active:   легке shadow (поточна в фокусі)
  - expanded: fullscreen режим для читання

Header:
  [● Dot] [Ім'я]     [Відкрити ↗] [Копіювати] [⋯ Меню]

Footer (2 кнопки, не 3):
  [→ Надіслати іншим]  [↓ Поглибити]
  
  При hover на кнопку — tooltip: "Генерує промпт для копіювання"
```

### PromptPanel

```
НЕ внизу сторінки — відкривається як drawer справа або popup над карткою

Вхід: promptType, sourceParticipant, targetParticipant, context
Вихід: onCopy, onClose

Вміст:
  ┌─────────────────────────────┐
  │ Промпт для Gemini           │
  │ (відповідь Claude → Gemini) │
  ├─────────────────────────────┤
  │ [текст промпту]             │
  │                             │
  ├─────────────────────────────┤
  │ [Копіювати]  [Відкрити →]  │
  └─────────────────────────────┘
```

### SynthesisBlock

```
Завжди видимий (не внизу) — під питанням або як sticky блок

Стани:
  - empty:     "Дистиляція з'явиться після заповнення відповідей"
  - generated: структурований текст з розділами
  - editing:   textarea для ручного редагування

Структура згенерованої дистиляції:
  ## Спільне (де всі AI сходяться)
  → ...

  ## Унікальне від [Claude]
  → ...

  ## Суперечності
  → ...

  ## Висновок
  → ...
```

## 11. Промпт-шаблони {#промпти}

### Режим Синтез (synthesis)

```
[Питання]: {question}

[{sourceName} пропонує]:
{response}

Твоє завдання — СИНТЕЗ:
1. Що з цього ти повністю підтримуєш? Чому?
2. Що можна розвинути або уточнити?
3. Яку додаткову перспективу ти додаєш, якої тут немає?
Будь конкретним, без повторення вже сказаного.
```

### Режим Дебати (debate)

```
[Питання]: {question}

[Позиція {sourceName}]:
{response}

Твоє завдання — ЗАПЕРЕЧИТИ:
1. Знайди найслабший аргумент у цій позиції
2. Поясни чому ти не погоджуєшся
3. Запропонуй свою альтернативну позицію
Говори впевнено, захищай свою точку зору.
```

### Режим Критика (critique)

```
[Питання]: {question}

[Відповідь для аналізу — {sourceName}]:
{response}
```
